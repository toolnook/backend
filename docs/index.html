Toolnook for Stellar · Backend

A steadier path to Stellar data.

Horizon is the web API apps use to ask Stellar about accounts, payments, and ledgers. Toolnook Backend is an optional gateway that helps manage those requests between your app and Stellar.

How does a gateway help?

Without a gateway, your application sends requests directly to an upstream API. This service can sit in the middle and apply helpful safeguards.

Your app→Toolnook Backend→Horizon or Soroban RPC

Reuse recent answers

A cache keeps some recent read responses briefly, reducing repeated calls for the same data.

Control request speed

A rate limit caps how quickly requests pass through, helping your app avoid sending a burst of traffic.

Handle outages gently

A circuit breaker pauses calls after repeated failures, instead of letting one failing service cause a wider chain of failures.

Try it on your computer

You need Node.js 18 or newer. These steps start the gateway locally; they do not deploy an app to Stellar.

1

Download and install

git clone https://github.com/toolnook/backend.git
cd backend
npm ci
npm run build
2

Make your config

cp config.example.yaml config.yaml

Open config.yaml and check the network and routes. Use public for the live network or testnet for experiments.

3

Start the service

npm start

Your local app can now send requests to this gateway using the port and routes in your config.

A few useful words

Horizon

A web service for reading Stellar network data, such as accounts and payments.

Testnet and public network

Separate Stellar environments. Testnet is for learning and testing; public is the live network.

Soroban RPC

A web service used by applications to interact with Soroban smart contracts.

Good first step: keep test and public network settings separate. Confirm the selected network before pointing an app at it.
